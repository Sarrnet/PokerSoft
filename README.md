# PokerSoft

Ассистент по принятию решений в безлимитном Техасском холдеме (No-Limit
Hold'em). Для любой раздачи выдаёт **две** рекомендации рядом, а не одну:

- **МАТЕМАТИКА** — GTO-ориентированный бейзлайн: эквити против диапазона
  соперника, pot odds, minimum defense frequency (MDF), префлоп-чарты по
  позиции, отдельная логика пуш/фолд для короткого стека.
- **ПРО-СТИЛЬ** — та же самая ситуация, но с поправкой на реально
  наблюдаемую статистику конкретного соперника (VPIP, PFR, частота фолда на
  к-бет, частота фолда на 3-бет, фактор агрессии). Это эксплойт-отклонение
  от сбалансированной линии — то, что делает за столом думающий игрок,
  когда видит конкретные слабости конкретного человека, а не играет
  "в вакууме" против абстрактного диапазона.

Три режима запуска:

| Режим | Что делает | Нужны ли внешние зависимости |
|---|---|---|
| `manual` | Ручной ввод раздачи в терминале → мгновенная рекомендация | Нет, только stdlib Python |
| `calibrate` | Разметка регионов экрана под конкретный покерный клиент | mss, Pillow, tkinter |
| `run` | Захват экрана в реальном времени + оверлей с подсказками | mss, opencv-python, pytesseract, numpy, Pillow |

## Область применения и этика

Это инструмент для **домашней игры с друзьями**, где применение подобного
помощника согласовано между всеми участниками: например, все играют через
одно приложение/на одном столе и знают, что кто-то использует ассистента,
либо это часть договорённостей конкретной игры.

**Не используйте это для игры на реальные деньги на сторонних онлайн-
платформах** (PokerStars, GGPoker, 888poker, partypoker и т.п.). Там
подсказки в реальном времени (RTA, real-time assistance) прямо запрещены
правилами платформ; их обнаружение ведёт к блокировке счёта и конфискации
средств. По сути это нечестная игра против других людей, поставивших
реальные деньги, — независимо от того, поймает вас платформа или нет.

Модуль захвата экрана рассчитан на калибровку под конкретный клиент/
раскладку стола и не пытается скрывать своё присутствие от какого-либо ПО
(нет обхода античит-защиты, нет маскировки процесса и т.п.) — это бытовой
инструмент для игры с друзьями, а не средство обхода защиты платформ.

## Установка

```bash
git clone <this repo>
cd PokerSoft
pip install -e .
```

Для режимов `calibrate`/`run` (захват экрана, OCR, распознавание карт)
дополнительно:

```bash
pip install -r requirements.txt
# и системный пакет tesseract-ocr, например на Ubuntu/Debian:
sudo apt install tesseract-ocr
```

Режим `manual` использует только модули `cards.py`, `evaluator.py`,
`equity.py`, `ranges.py`, `preflop_strength.py`, `opponent_model.py`,
`decision.py` — все они на чистом stdlib Python (3.10+), без сторонних
пакетов. Можно пользоваться сразу после `git clone`, без `pip install`.

## Быстрый старт: ручной режим

```bash
python -m pokersoft.app manual
```

Программа последовательно спросит:

1. Карты героя (`Ah Kd`).
2. Общие карты — пусто, если префлоп; 3/4/5 карт для флопа/тёрна/ривера.
3. Позицию героя (`UTG`/`HJ`/`CO`/`BTN`/`SB`/`BB`).
4. Стек героя в больших блайндах (bb).
5. Текущий банк (пот) в bb.
6. Сумму, которую нужно доколлировать, в bb (0, если ходит первым).
7. Число активных соперников в раздаче.
8. (Только префлоп) сколько рейзов было до героя: 0 — первым в банк,
   1 — против одиночного рейза, 2+ — против 3-бета и выше.
9. Опционально — имя соперника, чтобы копить по нему эксплойт-статистику
   между раздачами в рамках текущей сессии (см. следующий раздел о
   пределах этого механизма).

На выходе — обе рекомендации с пояснением текстом, почему выбран именно
такой ход. Пример вывода:

```
--- Рекомендация ---
Эквити: win=100.0% tie=0.0% lose=0.0% (n=4000)
МАТЕМАТИКА (GTO-базис): RAISE 15.0bb
  почему: Эквити 100% значительно выше требуемых 33% (pot odds) — рейзим на значение.
ПРО-СТИЛЬ (эксплойт): RAISE 15.0bb
  почему: Эквити 100% значительно выше требуемых 33% (pot odds) — рейзим на значение.
  [Недостаточно раздач по сопернику — эксплойт совпадает с GTO.]
```

## Как считается "МАТЕМАТИКА" (GTO-бейзлайн)

Код: `pokersoft/decision.py`, функции `_preflop_gto` и `_postflop_gto`.

**Префлоп:**

- Если стек ≤ 20 bb и никто ещё не рейзил — включается отдельная
  пуш/фолд-логика: порог "шовить" зависит от глубины стека и позиции
  (`threshold = 0.10 + depth_factor * 0.30 + position_bonus`), а сама рука
  сравнивается с этим порогом через **перцентиль силы** (см. ниже,
  `preflop_strength.py`) — не через захардкоженную таблицу.
- Если стек глубокий и никто не рейзил — рука героя проверяется на
  вхождение в диапазон открытия (RFI, raise-first-in) для его позиции. Эти
  диапазоны — `RFI_RANGES_6MAX` в `ranges.py`, ручные приближения к
  публично известным солверным чартам для 6-max, а не результат
  собственного солва.
- Если уже был один рейз — рука сравнивается с value-3-бет диапазоном
  (`THREEBET_VALUE_RANGES_6MAX`); если не входит, но попадает в топ 35%
  рук по перцентилю — колл; иначе фолд.
- Если было 2+ рейза (против 3-бета) — продолжать только с топ-6% рук.

**Постфлоп:**

1. Собирается предполагаемый диапазон соперника: либо явно заданный
   (`opponent_range_hint`), либо дефолтный "диапазон, с которым доходят до
   этой ситуации" (обобщённая широкая range-строка в `_default_opponent_range_str`).
2. Считается эквити руки героя против этого диапазона Монте-Карло
   симуляцией (`equity.py`, тысячи случайных розыгрышей оставшихся карт).
3. Считаются **pot odds** — `to_call / (pot + to_call)` — необходимое
   эквити для профитного колла, и **MDF** — `pot / (pot + bet)` — доля
   раздач, которую нужно защищать от блефа, чтобы соперник не мог
   профитно блефовать в любую руку.
4. Решение:
   - Ходит первым (`to_call == 0`): эквити ≥ 65% → бет на значение (~66%
     пота); эквити ≤ 30% против одного соперника → тоже бет (полу-блеф/
     блеф, балансирующий диапазон ставок теоретически); иначе чек.
   - Есть ставка соперника: эквити ≥ pot odds + 15% → рейз; эквити в
     пределах pot odds (± небольшой запас) → колл; ниже — фолд.

Это **не настоящий солвер** — солв постфлоп-дерева требует офлайн-компьюта
или заранее просчитанной стратегии (как PioSolver/GTO+/MonkerSolver), что
не укладывается в живой оверлей. Здесь используется разумное, математически
обоснованное приближение (эквити + pot odds + типовые размеры ставок), а не
точное равновесие.

## Как считается "ПРО-СТИЛЬ" (эксплойт-слой) — подробно

Код: `pokersoft/decision.py`, функция `_apply_exploit_adjustment`, и
`pokersoft/opponent_model.py`, класс `OpponentStats`.

### 1. Какая статистика копится по каждому сопернику

`OpponentStats` — это набор простых счётчиков за один игровой день/сессию:

| Метод | Что считает | Покерный смысл |
|---|---|---|
| `vpip()` | % раздач, где соперник добровольно вложил деньги префлоп | Лузовость/тайтовость старта |
| `pfr()` | % раздач, где он рейзил префлоп | Агрессивность старта |
| `three_bet_pct()` | % 3-бетов от числа возможностей | Как часто он реагирует агрессией на рейз |
| `fold_to_cbet()` | % фолдов на ставку после того как был агрессором на предыдущей улице | "Сдаётся" ли он на давление |
| `fold_to_3bet()` | % фолдов, когда его рейз пере-рейзили | Насколько крепко держит диапазон под давлением |
| `aggression_factor()` | (агрессивные действия постфлоп) / (пассивные действия постфлоп) | Общая склонность давить vs. отвечать пассивно |

### 2. Порог доверия к выборке

Ничего из этого не используется, пока `hands_observed < 15`
(константа `MIN_SAMPLE` в `opponent_model.py`). Если раздач по игроку
меньше — `_apply_exploit_adjustment` возвращает **ту же самую**
рекомендацию, что и GTO-бейзлайн, с явной пометкой в объяснении:
"Недостаточно раздач по сопернику — эксплойт совпадает с GTO." Это
намеренная защита от переоценки шума: 3 фолда на к-бет из 3 раз — не
статистика, а совпадение.

### 3. Сами правила отклонения от GTO

Когда данных достаточно, применяется набор явно прописанных покерных
эвристик (это не солвер и не ML-модель — просто закодированные
профессиональные правила большого пальца), по одному условию за раз:

**Постфлоп, ход первым (`to_call == 0`):**

- `fold_to_cbet ≥ 60%` и GTO говорит "чек" → заменяем на **бет** (~50%
  пота). *Логика:* если соперник пасует на ставки чаще, чем это нужно
  математически для баланса, ставить выгоднее чека почти независимо от
  силы своей руки — GTO держит чек в диапазоне ради баланса против
  чек-рейзов, но конкретно этот игрок редко наказывает нас чек-рейзом.
- `fold_to_cbet ≤ 30%` (соперник — "станция") и GTO говорит "бет", но
  эквити руки < 55% → заменяем на **чек**. *Логика:* тонкий полу-блефовый
  бет не окупается против того, кто почти всегда колирует — вы просто
  сливаете фишки без причины дважды: сначала ставкой, потом на реке.

**Постфлоп, есть ставка соперника (`to_call > 0`):**

- `aggression_factor < 0.5` (соперник пассивен, редко рейзит/блефует) и
  GTO говорит "колл" при эквити ≥ 55% → заменяем на **рейз** (~75% пота).
  *Логика:* против пассивного игрока рейз на значение можно делать шире,
  чем допускает сбалансированная стратегия, — он почти не отыгрывается
  блефом, если ошибётся, так что риск рейза минимален, а апсайд в виде
  дополнительных фишек — реален.

**Префлоп:**

- Соперник тайтовый (`vpip < 16%`), GTO уже говорит "рейз-опен" →
  рекомендация не меняется, но добавляется пояснение, что открытие тем
  более корректно (можно даже немного расширить диапазон открытия).
- Соперник часто пасует на 3-бет (`fold_to_3bet ≥ 70%`) и GTO говорит
  "фолд" на чужой рейз → заменяем на **3-бет-блеф** (пот + 3×колл).
  *Логика:* если он бросает карты на 3-бет так часто, даже слабая рука
  забирает банк заметно чаще, чем необходимо для профита блефа.
- Соперник лузово-пассивный ("calling station": `vpip ≥ 42%`,
  `aggression_factor < 0.7`) и GTO говорит "фолд" → **фолд остаётся
  фолдом**, с пояснением "не пытайтесь его выбить блефом, он всё равно
  колирует". Это пример, когда эксплойт-логика **намеренно не отклоняется**
  от GTO — она также умеет объяснять, почему давить не стоит.

Если ни одно правило не сработало — рекомендация совпадает с GTO с
пометкой, что статистика есть, но в этой конкретной ситуации она ничего не
меняет.

### 4. Важная честная оговорка: механизм есть, автосбора данных — нет

Сам эксплойт-слой (`OpponentStats` → `_apply_exploit_adjustment`) полностью
реализован и покрыт тестами (`tests/test_decision.py`), но **сейчас нигде
не подключён автоматический сбор этой статистики из живой игры**:

- В ручном режиме (`app.py: run_manual`) можно указать *имя* соперника —
  но CLI не даёт способа ввести его реальные VPIP/PFR/фолды. Объект
  `OpponentStats` создаётся с нулевыми счётчиками (`OpponentBook.get`),
  поэтому `hands_observed` останется 0, и "ПРО-СТИЛЬ" не будет отличаться
  от GTO, пока кто-то не вызовет `record_*`-методы вручную из кода (или
  пока в CLI не добавят соответствующий ввод — см. раздел "Дальнейшее
  развитие").
- В real-time режиме (`capture/table_state.py`) реализовано распознавание
  только карт героя/борда и чисел (банк, стек, колл) — распознавания
  *действий других игроков* (кто зачекал, кто зафолдил на к-бет и т.п.)
  там нет, соответственно статистика не накапливается автоматически даже
  при живом захвате экрана.

Иначе говоря: **принцип работы про-стиля описан выше и он рабочий**
(проверяем это юнит-тестами, передавая `OpponentStats` вручную), но чтобы
он реально включался в игре, недостаёт "проводки" от источника данных
(ваших наблюдений или распознанных действий) до объекта `OpponentStats`.

## Real-time режим: захват экрана

1. `python -m pokersoft.app calibrate --layout my_table` — один раз для
   каждой раскладки стола (размер окна/зум клиента). Появится скриншот,
   нужно поочерёдно выделить рамкой: 2 карты героя, 5 слотов общих карт,
   текст банка, текст стека героя, текст суммы колла. Результат сохраняется
   в `data/profiles/my_table.json`.
2. Распознавание карт работает через template matching (`opencv`), а не
   через жёстко вшитые координаты пикселей — но ему нужны образцы рангов
   (`data/templates/my_table/ranks/2.png` … `A.png`) и мастей
   (`data/templates/my_table/suits/s.png` … `c.png`), вырезанные из
   скриншотов именно вашего клиента и с тем же масштабом, с которым вы
   калибровались. Заготовьте их вручную (любой графический редактор или
   скрипт на `PIL`) — без них `run` откажется стартовать с понятной
   ошибкой (`FileNotFoundError` из `card_reader.py`).
3. `python -m pokersoft.app run --layout my_table --big-blind 1.0` —
   запускает оверлей поверх всех окон (`ui/overlay.py`), обновляющийся
   каждые ~0.4 секунды (`REFRESH_MS`).

Это честно ограниченный, но рабочий каркас: надёжное распознавание
произвольного покерного клиента "из коробки" не решается в общем виде без
адаптации под конкретную раскладку — поэтому калибровка обязательна и
специфична для вашего клиента/разрешения/темы.

```
                              тайбрейки), evaluate_best — лучшая комбинация
                              из 5-7 карт (проверяет все C(7,5)=21 вариантов)

                                   + _apply_exploit_adjustment
  capture/
    profile.py                      TableProfile — координаты регионов

                                     сохранение/загрузка JSON

    card_reader.py                    Распознавание карт через OpenCV
                                       template matching (образцы рангов

    ocr.py                             Чтение чисел (банк/стек) через
                                        pytesseract
    table_state.py                     TableReader — собирает
                                        RawObservation из захваченных
                                        регионов
  ui/
    overlay.py                          Always-on-top tkinter-оверлей,
                                         опрашивает поставленную функцию
                                         каждые REFRESH_MS миллисекунд
  app.py                                 CLI: manual / calibrate / run

tests/
  test_evaluator.py, test_equity.py, test_ranges.py, test_decision.py
data/
  preflop_strength.json (кэш, генерируется автоматически, в .gitignore)

```

## Известные ограничения и что НЕ доделано

- **Префлоп-чарты и постфлоп bet-sizing** — ручные приближения к солверным
  стратегиям, а не результат реального real-time решения игры. Считайте
  их разумным, математически обоснованным бейзлайном, а не заменой
  полноценного солвера (PioSolver/GTO+ и т.п.) для глубокого анализа.
- **Эквити считается Монте-Карло** (несколько тысяч испытаний на решение)
  — для живого оверлея этого достаточно по скорости и точности (единицы
  процентов погрешности), но это не точное перечисление всех исходов.
- **Сбор эксплойт-статистики не подключён к источникам данных** (см. раздел
  выше) — механизм готов и протестирован, но ни ручной ввод, ни захват
  экрана пока не вызывают `OpponentStats.record_*`.
- **Модель соперника хранится только в памяти процесса** — обнуляется при
  перезапуске; для статистики между сессиями нужна отдельная база (файл/
  SQLite), которой пока нет.
- **Распознавание карт/чисел с экрана требует калибровки** под конкретный
  клиент, разрешение экрана и зум; при смене масштаба/темы клиента
  калибровку и образцы карт нужно готовить заново.
- **Тайбрейк на равных руках при 3+ игроках** в `equity.py` использует
  упрощение "поделить банк 50/50", что чуть менее точно для точных
  трёхсторонних split-потов, но не влияет на итоговое win/lose.

## Тесты

```bash
pip install pytest
pytest
```

21 тест покрывают оценщик комбинаций (в т.ч. "колесо" A-2-3-4-5, кикеры,
флеш vs стрит), Монте-Карло эквити (известные бенчмарки: AA vs случайная
рука ≈ 85%, KK vs AA ≈ 17-18%), парсер диапазонов и движок решений (pot
odds, MDF, вход в диапазон открытия, пуш/фолд, срабатывание и не-срабатывание
эксплойт-поправок).

## Дальнейшее развитие

Наиболее ценные следующие шаги, если понадобится довести до полностью
живого использования:

1. Добавить в `manual`-режим ввод статистики по сопернику (или команды
   "запиши: он зафолдил на мой кбет") вместо пустого `OpponentStats`.
2. Научить `capture/table_state.py` распознавать действия других игроков
   (фолд/чек/колл/бет/рейз по изменению их ставки/статуса на столе) и
   вызывать соответствующие `OpponentStats.record_*` — тогда "ПРО-СТИЛЬ"
   в real-time режиме заработает по-настоящему, без ручного ввода.
3. Сохранять `OpponentBook` между сессиями (JSON или SQLite в `data/`).
4. При желании — заменить постфлоп-эвристику на реальный (хотя бы упрощённый)
   солвер или предпосчитанные стратегии для типовых текстур борда.
