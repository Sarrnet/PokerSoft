# PokerSoft

Ассистент по принятию решений в безлимитном Техасском холдеме. Для любой
раздачи выдаёт две рекомендации рядом:

- **МАТЕМАТИКА** — GTO-ориентированная база: эквити против диапазона
  соперника, pot odds, minimum defense frequency, префлоп-чарты по позиции,
  пуш/фолд для короткого стека.
- **ПРО-СТИЛЬ** — та же ситуация, но с поправкой на реально наблюдаемую
  статистику конкретного соперника (VPIP/PFR/фолд на кбет/фолд на 3-бет и
  т.д.), то есть эксплойт-отклонение от сбалансированной линии, как это
  делает думающий игрок за столом.

Есть три режима запуска: `manual` (ввод раздачи руками, работает сразу без
установки доп. зависимостей), `calibrate` и `run` (захват экрана в реальном
времени + оверлей с подсказками).

## Область применения и этика

Это инструмент для **домашней игры с друзьями**, где применение подобного
помощника согласовано между всеми участниками (например, все играют через
одно приложение и знают, что кто-то использует ассистента, либо это часть
правил конкретной игры). **Не используйте это для игры на реальные деньги
на сторонних онлайн-платформах (PokerStars, GGPoker, 888poker, partypoker
и т.п.)** — там подсказки в реальном времени (RTA, real-time assistance)
прямо запрещены правилами, их обнаружение ведёт к блокировке счёта и
конфискации средств, а по сути это нечестная игра против других людей,
поставивших реальные деньги. Модуль захвата экрана рассчитан на калибровку
под конкретный клиент/раскладку стола и не пытается скрывать своё
присутствие от какого-либо ПО — это учебный/бытовой инструмент, а не
средство обхода защиты платформ.

## Установка

```bash
pip install -e .
# для режимов calibrate/run (захват экрана, OCR, распознавание карт):
pip install -r requirements.txt
# plus системный пакет tesseract-ocr (для pytesseract), например:
#   sudo apt install tesseract-ocr
```

Режим `manual` использует только модули `pokersoft.cards/evaluator/equity/
ranges/decision/opponent_model/preflop_strength` — все они на чистом stdlib,
без сторонних пакетов.

## Быстрый старт (без калибровки)

```bash
python -m pokersoft.app manual
```

Программа спросит карты героя, борд (пусто — префлоп), позицию, стек, банк,
сумму колла, число соперников — и выведет обе рекомендации с объяснением.
Если вы вводите имя соперника несколько раздач подряд, статистика по нему
копится в памяти сессии и начинает влиять на "ПРО-СТИЛЬ" после 15+
наблюдённых раздач (порог `MIN_SAMPLE` в `opponent_model.py`).

## Real-time режим (захват экрана)

1. `python -m pokersoft.app calibrate --layout my_table` — один раз для
   каждой раскладки стола (размер окна/зум клиента). Появится скриншот,
   нужно поочерёдно выделить рамкой: 2 карты героя, 5 слотов общих карт,
   текст банка, текст стека героя, текст суммы колла. Результат сохраняется
   в `data/profiles/my_table.json`.
2. Распознавание карт работает через template matching (`opencv`), а не
   через жёстко вшитые координаты пикселей — но ему нужны образцы рангов
   (`data/templates/my_table/ranks/2.png` … `A.png`) и мастей
   (`data/templates/my_table/suits/s.png` … `c.png`), вырезанные из
   скриншотов именно вашего клиента. Заготовьте их вручную (любой
   графический редактор/скрипт с `PIL`) — без них `run` откажется
   стартовать с понятной ошибкой.
3. `python -m pokersoft.app run --layout my_table --big-blind 1.0` —
   запускает оверлей поверх всех окон, обновляющийся ~2 раза в секунду.

Это честно ограниченный, но рабочий каркас: надёжное распознавание
произвольного покерного клиента "из коробки" не решается в общем виде без
адаптации под конкретную раскладку — поэтому калибровка обязательна.

## Архитектура

```
pokersoft/
  cards.py              карты, парсинг, колода
  evaluator.py           оценщик 5-7 карточных комбинаций
  ranges.py               нотация диапазонов + базовые префлоп-чарты (6-max)
  equity.py                Монте-Карло эквити рука/диапазон vs диапазон(ы)
  preflop_strength.py       перцентиль силы всех 169 префлоп-рук (считается
                             Монте-Карло, кэшируется в data/preflop_strength.json)
  opponent_model.py          статистика по соперникам (VPIP/PFR/AF/фолды)
  decision.py                  движок решений: GameState -> (GTO, эксплойт)
  capture/
    profile.py                  описание координат регионов для раскладки стола
    screen.py                    захват экрана (mss)
    calibrate.py                  GUI для разметки регионов
    card_reader.py                 распознавание карт (template matching)
    ocr.py                          чтение чисел (банк/стек) через tesseract
    table_state.py                  сборка GameState из захваченных регионов
  ui/overlay.py                    always-on-top оверлей с рекомендациями
  app.py                            CLI: manual / calibrate / run
```

## Ограничения, о которых стоит знать

- Префлоп-чарты и пост-флоп bet-sizing — ручные приближения к
  солверным стратегиям, а не результат реального real-time решения игры
  (это отдельная и намного более тяжёлая задача, требующая офлайн-компьюта
  или предпосчитанной стратегии). Они дают разумный, math-grounded бейзлайн,
  но не заменяют полноценный солвер (PioSolver/GTO+ и т.п.) для глубокого
  анализа.
- Эквити считается Монте-Карло (несколько тысяч испытаний на решение) —
  для реалтайм-оверлея этого достаточно по скорости и точности (единицы
  процентов погрешности), но это не точное перечисление.
- Модель соперника — простой набор счётчиков за сессию, обнуляется при
  перезапуске; для долгосрочных читов нужна отдельная база данных.
- Распознавание карт/чисел с экрана требует калибровки под конкретный
  клиент и разрешение экрана; при смене масштаба/темы клиента калибровку
  нужно повторить.
